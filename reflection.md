# Reflection

Copilot produced a structure for a couple of functions in the data cleaning script, which was one of the main things it created through working on this project. Copilot originally suggested functions such as `clean_column_names()`, `handle_missing_values()`, `remove_invalid_rows()` based on what I wrote in comments detailing the tasks each function should complete. I mostly prompted Copilot by writing comments above the column names that are in pieces of code that tell me what I want to do, like cleaning column names, removing missing values, or filtering invalid rows. In some cases I also started writing part of a function name or a line of code and Copilot recommended where to put the rest. 

Copilot assisted in building a great deal of original code, but I still needed some changes to run the script. What came up in my mind of course was that the column names did not match the dataset. The code originally referenced `quantity`, however upon reviewing the dataset I discovered the column name that it contained was `qty`. The script updated every component regarding this column from beginning to end to give you the correct names. I made changes to missing value handling logic like substituting blank spaces with missing values and subsequently removing rows with incomplete values. I also modified the wrong row filter part by transforming the `price` and `qty` columns to numeric value, using `pd.to_numeric()` because the script was initially impotent to compare numbers with text values. 

This project helped me gain deep knowledge on how to clean and prepare datasets in Python and pandas for analysis. Prior to these, I grasped the concept of data cleaning in general but had less practical knowledge of this in a coding environment. I also learned how to load CSV files into DataFrames, set up column names standardization and removal of missing data, how to properly remove missing data, and check numerical data. I also learned the significance of indentation and function order to use in python code, because of a few mistakes that had occurred when functions were indented incorrectly in code and were not indented and called before defined or with function declarations were made. 

I discovered that Copilot is incredibly helpful in getting the starter code ready quick-and-easy, however, still needs proper code review and debugging too. One positive of Copilot was that functions generated pretty fast after I described this task in comments. It properly recommended logic for standardizing the column names, for example, and replacing spaces with underscores. But a limitation was that Copilot occasionally produced code that didn’t exactly fit my dataset, in which I’d use the wrong column names or recommend a certain logic before certain variables were defined. As such, I realised Copilot operates best as a tool to support project as it lacks the ability to complete a project on its own. However, there’s still the need to review the developed code and understand how it works to ensure that the program works properly.
